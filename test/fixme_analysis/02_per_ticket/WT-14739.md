## What this FIXME asks for
Follower (secondary) nodes in disaggregated storage currently skip the shutdown checkpoint entirely because the checkpoint code does not yet know how to skip shared (layered) tables. Writing to shared tables from a follower is forbidden, so the safest option is to skip the shutdown checkpoint altogether. The FIXME asks for the checkpoint logic to be enhanced so it can skip only the shared tables while still checkpointing local-only state, allowing followers to perform a proper shutdown checkpoint.

## Importance: MEDIUM
**Reasoning**: Skipping the shutdown checkpoint on followers means those nodes cannot avoid RTS (rollback to stable) on the next startup, potentially increasing restart latency. A recent comment in the Jira ticket (Etienne Petrel, 2026-03-10) suggests the current behavior may actually be the desired final state and that the FIXME may simply need to be removed rather than fixed. Regardless, there is no correctness issue — followers do not author data, so the missing checkpoint does not cause data loss. The main risk is unnecessary RTS overhead on follower restarts.
