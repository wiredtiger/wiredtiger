## What this FIXME asks for
In the ingest-drain path (migrating updates from the ingest btree to the stable btree during step-up), the code at line 475 directly calls `__wt_upd_alloc` / `__wt_upd_alloc_tombstone` and manually constructs a `WT_UPDATE` struct with internal fields (`txnid`, `prepare_state`, `prepared_id`, etc.) to represent a non-prepared update being moved to the stable table. This is a layering violation because `conn_layered_ingest.c` (a connection-level file) reaches into transaction/update internals that belong to a lower layer. The author acknowledges this but had no better solution at the time.

## Importance: MEDIUM
**Reasoning**: The violation itself works correctly in the current implementation but is fragile: any change to `WT_UPDATE` internals (field layout, new state flags, allocation requirements) must also be reflected in this ingest-drain code, which is not obviously co-located with the update layer. A missed update here during a refactor could corrupt transaction visibility for updates migrated during step-up, leading to wrong read results or prepared-transaction inconsistencies.
