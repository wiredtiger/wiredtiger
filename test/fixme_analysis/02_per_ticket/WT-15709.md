## What this FIXME asks for
Disaggregated storage uses page deltas to avoid rewriting full pages on every reconciliation. However, when an internal page is split (i.e., a single ref generates multiple child keys — `mod_multi_entries > 1`), the reconciler cannot currently build a correct delta because it cannot delete the previously-written keys for that ref. The three FIXMEs mark the places where delta building is explicitly suppressed for split pages: (1) in `__rec_row_merge` when a ref has multiple entries, (2) in the internal-page reconciliation loop when a split flag or first-key change is detected, and (3) in the HS wrapup where `multi->supd` is preserved (not freed) for disagg to allow future delta construction. The underlying work is to design a delta encoding that handles the split case.

## Importance: HIGH
**Reasoning**: HIGH. This is a known performance limitation of the disaggregated storage path — pages that have ever split must be written in full rather than as deltas, increasing write amplification and object storage costs. For workloads with high insert/update rates that trigger splits, this negates a key efficiency goal of the disagg architecture. The suppressed supd freeing in rec_write.c also means memory is held longer than necessary.
