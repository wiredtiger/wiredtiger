## What this FIXME asks for
`test_truncate15` validates that a readonly database connection can correctly read pages that were fast-truncated, without causing cache-stuck conditions. The entire test class is decorated with `@wttest.skip_for_hook("disagg", "readonly connections not supported yet")`, referencing WT-14582. The FIXME asks for readonly-connection support to be added to the disaggregated/layered storage path so that this test (and the underlying use case) can be enabled.

## Importance: MEDIUM
**Reasoning**: Readonly connections are used by MongoDB for secondaries and diagnostic tools. The inability to open a disaggregated database in readonly mode is a feature gap that limits the operational flexibility of the disaggregated storage mode. There is no crash or corruption risk — the feature is simply blocked — but it could affect deployments that rely on readonly secondaries with disaggregated storage.
