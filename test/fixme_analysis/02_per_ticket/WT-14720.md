## What this FIXME asks for
In `__wt_page_out`, disaggregated storage checks that a page being discarded has not been reconciled ahead of the materialization frontier, using `old_rec_lsn_max`. The FIXME notes that this comparison is conceptually flawed: there is no single meaningful LSN comparison point here. Specifically, "scrub eviction" (which retains data in the block cache) is a false-positive case — the check currently increments a stat for it even though no actual read will be issued. The fix requires redesigning the check to differentiate scrub eviction from regular eviction, and to choose the correct LSN field (`old` vs `new`) based on whether a dirty eviction has occurred.

## Importance: MEDIUM
**Reasoning**: The current check produces false-positive statistics (`cache_eviction_ahead_of_last_materialized_lsn`), which could mislead operators monitoring disaggregated storage health. A deeper risk is that the wrong LSN field (`old_rec_lsn_max` vs the new value) could cause the check to miss or falsely flag legitimate evictions in certain reconciliation states, potentially leading to stale data being served from disaggregated storage in edge cases.
