## What this FIXME asks for
WiredTiger currently explicitly excludes metadata cursors from the cursor cache (to avoid interference with named checkpoints). This means that cursor open statistics in layered/disaggregated tests are inflated by uncached metadata cursor opens, making it impossible to set tight expected bounds for cursor creation counts. The FIXME asks that once metadata cursor caching is implemented (WT-17299), the empirically-determined slack bounds in the test can be tightened to precisely expected values. The Jira description also notes a crash (bad memory access during session close) when metadata cursor caching is naively enabled, indicating the fix requires deeper investigation of cursor lifecycle management.

## Importance: LOW
**Reasoning**: This is a performance improvement and test precision issue. The lack of metadata cursor caching increases the overhead of metadata-heavy workloads (which are common in disaggregated storage where schema operations flow through the shared metadata table). However, it does not cause correctness issues and the current behavior is stable. The test bounds work as-is, just with less precision.

## Test Coverage: PARTIAL
**Relevant tests**: test/suite/test_layered98.py (directly tracks cursor creation stats), test_layered*.py generally
**Gap**: The cursor creation count bounds in test_layered98.py are deliberately loose to accommodate uncached metadata cursors (e.g., follower limit is 325, which is much higher than what would be expected if metadata cursors were cached). This means excessive cursor opens in the metadata path could go undetected within those wide margins.
