## What this FIXME asks for
In `__meta_live_restore_to_meta`, the code directly accesses the internal block manager structure (`bm->block->fh->handle`) to obtain the file handle needed to call `__wt_live_restore_fh_to_metadata`. This bypasses the block manager's abstraction layer. The FIXME requests a proper block manager API be created so that callers in the metadata layer do not need to reach into block manager internals directly.

## Importance: MEDIUM
**Reasoning**: Directly accessing `bm->block->fh->handle` creates a tight coupling between the checkpoint metadata code and the block manager's internal layout. Any refactoring of the block manager's struct layout (e.g., for disaggregated or tiered storage) could silently break this access path. A proper API would enforce the abstraction boundary and make future block manager changes safer. There is also an assertion `bm->is_multi_handle == false` immediately before, suggesting this shortcut is already known to be unsafe for multi-handle configurations.
