## What this FIXME asks for
The random cursor implementation for layered tables always checks the stable table first and only falls back to the ingest table when the stable table is empty or absent. This means the probability of returning a record from the ingest table is not proportional to its size relative to the stable table. The fix would weight the random selection between stable and ingest tables by their relative sizes so that random sampling is statistically representative of the full table contents.

## Importance: LOW
**Reasoning**: The ingest table is intended to be small (due to frequent checkpoints), so the statistical skew is minimal in practice. This is a sampling quality issue rather than a correctness bug — random cursors still return valid records. However, workloads that rely on random sampling for representative statistics (e.g. cardinality estimation, sampling-based analytics) could be subtly skewed if ingest tables grow large. The ticket is P4/Minor and has been deprioritized to backlog.
