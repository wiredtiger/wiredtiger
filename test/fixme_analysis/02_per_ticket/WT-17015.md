## What this FIXME asks for
The current code uses relaxed atomic loads/stores (`__wt_atomic_load_double_relaxed` / `__wt_atomic_store_double_relaxed`) to read and write eviction dirty and updates triggers during checkpoint start and end. These are not safe for compare-and-swap because CAS on doubles is not supported on all platforms, and the inconsistent access pattern (direct reads mixed with atomic stores) can lead to races. The FIXME asks for a consistent, safe API for modifying and reading these threshold values, potentially by representing them as integers (fixed-point) or by using a pointer-swapped config snapshot struct.

## Importance: MEDIUM
**Importance**: MEDIUM  
**Reasoning**: The current workaround uses relaxed atomics which avoids the reconfig lock timeout bug (WT-16613), but the inconsistency in how triggers are read vs. written means there is a latent race condition risk. In production, a misread trigger value could cause suboptimal eviction pressure during checkpoint, potentially causing cache pressure or OOM scenarios, but the immediate crash risk is low.
