## What this FIXME asks for
At the entry point of `__wt_os_live_restore_fs()` — the function that sets up the live-restore file system — there is an early guard that returns `EINVAL` if the connection is opened with `readonly=true`. The comment says this restriction should be removed once live restore is made compatible with readonly mode. Supporting readonly + live restore would allow a standby or audit process to open a live-restore database in read-only mode while migration is in progress.

## Importance: MEDIUM
**Reasoning**: The restriction is enforced gracefully (returns an error rather than crashing), but it blocks a legitimate use case: opening a database that is undergoing live restore in readonly mode. This is particularly relevant for MongoDB secondaries or diagnostic tools that need read access during migration. Without this, users must complete the live restore before any readonly open is possible.
