## What this FIXME asks for
Layered (disagg) cursors do not support the `checkpoint=...` configuration option, so the `checkpoint=WiredTigerCheckpoint` cursor used by `test/checkpoint` for consistency verification and by several Python tests is skipped or bypassed when running in disagg mode. The FIXMEs ask for implementing support for opening the last checkpoint (`checkpoint=WiredTigerCheckpoint`) on a layered table, which would allow `test/checkpoint`'s `verify_consistency` to run without the disagg guard and would re-enable checkpoint-cursor-based mirror verification in format stress tests.

## Importance: HIGH
**Reasoning**: Four separate skip guards suppress checkpoint-cursor verification across the primary checkpoint stress harness (`test/checkpoint`) and the format stress test. This means the correctness of disagg checkpoints is never verified by cursor-based consistency checks, which are the main mechanism for catching checkpoint corruption bugs. The ticket is tagged as a "New Feature" but blocking test coverage makes it functionally a test-coverage gap with production-quality implications.

## Test Coverage: UNCOVERED
**Relevant tests**: `test/checkpoint/checkpointer.c`, `test/format/checkpoint.c`, `test/format/format_prepare_discover.c` — all have the verification steps conditionally disabled for disagg.
**Gap**: No existing test exercises a `checkpoint=WiredTigerCheckpoint` cursor on a layered table. The consistency verification that would catch checkpoint-write bugs in disagg mode is entirely absent. Python tests that rely on last-checkpoint cursors are also not exercised on layered tables.
