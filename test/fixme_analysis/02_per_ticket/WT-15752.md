## What this FIXME asks for
The statistic macros (`WT_STAT_WRITE`, `WT_STAT_SET_BASE`, `WT_STAT_DECRV_BASE`, `WT_STAT_INCRV_BASE`, etc.) currently use `__wt_tsan_suppress_store_int64` / `__wt_tsan_suppress_sub_int64` / `__wt_tsan_suppress_add_int64` wrappers, which are TSAN-suppression shims around non-atomic loads and stores. The FIXME, placed at the top of this section, requests that all these suppressions be replaced with proper atomic operations (or at minimum relaxed-order atomics) so that TSAN can run without false suppressions. This is a follow-up to WT-15345, which addressed the bulk of TSAN warnings; the remaining harder cases in statistics were deferred here.

## Importance: MEDIUM
**Reasoning**: MEDIUM. The TSAN suppressions mean that genuine data races in statistics code are invisible in CI. While statistics are inherently fuzzy and a race rarely causes a correctness problem, the widespread use of suppress wrappers also risks masking a real synchronization bug hiding behind a stat update. Fixing this restores TSAN's ability to catch actual races.

## Test Coverage: PARTIAL
**Relevant tests**: TSAN-enabled test runs across the full suite; any concurrent workload test (e.g., test/format, test/suite concurrent tests) would expose races once suppressions are removed.
**Gap**: Until the suppressions are lifted, no TSAN test can distinguish a true stat race from a benign one; there is no targeted test that checks stat macro memory ordering.
