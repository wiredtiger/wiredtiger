## What this FIXME asks for
The `WT_SESSION_IMPL::name` field is updated on every user-visible API entry/exit to track what operation a session is performing. The FIXME notes that the practical value of this field is unclear, and per the Jira description, it was found (in WT-16496) that when a session is used by multiple threads simultaneously the field can report the wrong name, causing debugging confusion rather than helping it. The task is to evaluate whether `session->name` provides meaningful diagnostic value and remove it if it does not.

## Importance: LOW
**Reasoning**: This is a code-quality and cleanup task. The field currently causes occasional misleading debug output under multi-threaded use, but there is no evidence it causes data corruption, crashes, or wrong query results. Removing it would simplify the session struct and eliminate a source of confusion in diagnostic output, but leaving it in place carries only minor risk.

Any removal would need to audit all callers of `session->name` (e.g. error messages, statistics) to confirm they still work correctly.
