## What this FIXME asks for
The test `test_drop_hs_truncate` verifies that dropping a table cleans up its history store entries. It is currently skipped because opening the history store cursor from a fresh session (without `WT_CURSTD_IGNORE_TOMBSTONE` set) makes all history store records appear invisible, causing an assertion failure (`0 != 2`). The underlying bug is that cursors opened directly on the history store may not automatically receive the `WT_CURSTD_IGNORE_TOMBSTONE` flag, while the passing behavior on develop is an artifact of cursor caching from checkpoint re-use. The fix likely involves setting `WT_CURSTD_IGNORE_TOMBSTONE` on `file:WiredTigerHS.wt` cursor opens and clearing it correctly on cache eviction.

## Importance: HIGH
**Reasoning**: The bug means that history store records can be silently invisible to a fresh session cursor, which could mask records that should be visible in the history store. If `WT_CURSTD_IGNORE_TOMBSTONE` is missing from direct HS cursors, history store reads from non-checkpoint-cached sessions (e.g. during recovery or certain RTS paths) could return wrong results, which is a correctness risk. The test skip means this regression path is currently unprotected.
