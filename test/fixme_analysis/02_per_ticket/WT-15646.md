## What this FIXME asks for
When `__wt_session_get_dhandle()` is called with a URI that does not exist in the metadata (e.g., the legacy LAS/lookaside URI checked in `__hs_cleanup_las()`), the current code unconditionally allocates and inserts a new dhandle into `conn->dhqh` before discovering the URI is absent. The FIXME asks for a metadata pre-check before allocation so that non-existent URIs do not pollute the dhandle queue. The test_sweep07 workaround sleeps 2 seconds at startup to let the spurious empty LAS dhandle be swept away before checking sweep statistics, masking the underlying inefficiency.

## Importance: MEDIUM
**Reasoning**: MEDIUM. The spurious dhandle allocation is wasteful (CPU, memory, sweep work) and produces a false entry in sweep statistics that skews test assertions — hence the 2-second sleep workaround. It is not a data-correctness bug today, but if LAS cleanup is triggered on every connection open it adds measurable overhead at startup.

## Test Coverage: PARTIAL
**Relevant tests**: test/suite/test_sweep07.py — this test directly exposes the problem via its sleep workaround and sweep-count assertions.
**Gap**: The test works around the issue rather than testing for its absence; once the underlying fix lands the sleep and the associated comment should be removed, but there is no assertion that zero spurious dhandles are created.
