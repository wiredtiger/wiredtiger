## What this FIXME asks for
When the Python test suite is run with ASAN in parallel mode (multiple processes), ASAN warnings are silently suppressed, causing sanitizer errors to go undetected. The current workaround hard-exits with an error if `--parallel > 1` is combined with `--asan`, effectively serializing all ASAN test runs. The FIXME asks the team to determine the root cause of this suppression (suspected to be an ASAN limitation around forked processes, see upstream sanitizer issue #836), and to investigate whether other sanitizers (TSAN, MSAN, UBSAN) suffer the same issue.

## Importance: HIGH
**Reasoning**: Sanitizer warnings being silently hidden means memory safety bugs and leaks can go undetected during CI. The current mitigation (forcing sequential execution) significantly increases ASAN test run time and may delay CI feedback loops. More critically, if the root cause is not understood, the same issue could affect other sanitizers without any workaround in place.

## Test Coverage: PARTIAL
**Relevant tests**: test/suite/run.py (contains the workaround), companion ticket WT-16083 (fix memory leaks and re-enable CI failures)
**Gap**: There are no automated tests that verify ASAN warnings are reliably detected in parallel execution. The investigation itself (whether TSAN/MSAN/UBSAN are affected) has not been completed. No regression test guards against accidentally re-introducing parallel ASAN execution.
