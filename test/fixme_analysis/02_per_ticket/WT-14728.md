## What this FIXME asks for
`__layered_create_missing_ingest_table` (called during checkpoint pickup when a follower encounters a layered table whose ingest constituent is absent locally) duplicates configuration-building logic that also exists in `__create_layered` in `schema_create.c`. The FIXME asks whether this duplication should be eliminated by extracting the common ingest-table setup into a shared helper used by both paths.

## Importance: LOW
**Reasoning**: The duplication is a maintainability concern. If the ingest table configuration options change (e.g., new flags are added to `__create_layered`), the copy in `conn_layered.c` may be missed, causing newly-opened followers to create ingest tables with stale or missing configuration. This could lead to subtle behavioural differences between leader-created and follower-recovered ingest tables.
