## What this FIXME asks for
When a layered table is dropped, WiredTiger calls `pl_trim_table` to inform the PALI page log to discard all data for that table. The `start_lsn` argument (currently hardcoded to `0`) is intended to tell the page log the earliest LSN at which the table could have data, allowing page servers to skip contacting older page server epochs that predate the table's creation. The FIXME asks for the actual creation LSN to be tracked (likely in per-file metadata via `last_checkpoint_meta_lsn` at creation time) and passed here.

## Importance: LOW
**Reasoning**: The current behavior is functionally correct — passing `0` as `start_lsn` is conservative and safe; it simply means the page log must scan all page server epochs rather than a bounded subset. This is a performance optimization for table-drop cleanup, not a correctness issue. However, for large deployments with many page server epochs, the overhead could be significant.
