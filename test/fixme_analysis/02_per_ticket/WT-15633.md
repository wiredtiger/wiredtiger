## What this FIXME asks for
The `WT_BTREE` struct carries two timestamp fields: `prune_timestamp` (used only for ingest/disaggregated tables to track GC collection watermarks) and `checkpoint_timestamp` (used only for stable tables during checkpointing). Since these two use-cases are mutually exclusive per btree instance, the FIXME proposes combining them into a single field or a `union` to reduce per-btree memory overhead and clarify the invariant that only one of the two is meaningful at any time.

## Importance: LOW
**Reasoning**: LOW. This is a pure code-quality/memory-layout cleanup. There is no correctness risk from leaving the two fields separate — the space cost is one additional `wt_timestamp_t` per open btree handle, which is negligible. The main risk is that the split representation makes the semantic invariant ("only one is active") invisible, increasing the chance of a future developer accidentally using both.

## Test Coverage: PARTIAL
**Relevant tests**: none found specifically targeting this struct layout; both fields are exercised transitively by checkpoint tests and ingest/disagg tests.
**Gap**: No test verifies that the two fields are never both non-zero simultaneously for the same btree, so the mutual-exclusion invariant is untested.
