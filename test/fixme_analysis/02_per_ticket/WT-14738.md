## What this FIXME asks for
Layered tables currently have no support for custom collators — the collator fields are set to NULL when a layered table is opened, and any attempt to use a custom collator (e.g., the reverse collator) is explicitly rejected with EINVAL. The FIXME marks the placeholder where collator initialization logic should eventually be implemented. The open question is whether custom collators on layered tables should be supported at all, and if so, how collator state should be coordinated between the stable and ingest sub-tables.

## Importance: MEDIUM
**Reasoning**: Reversed B-trees (used in MongoDB for descending indexes) require `collator=reverse`, which is currently blocked for all layered tables. This directly prevents reverse-index support on disaggregated storage. WT-16254 had to explicitly disable reversed B-tree tests in disagg test scenarios as a workaround. Until this is resolved, disaggregated storage cannot support descending indexes, which is a functional gap for production use.
