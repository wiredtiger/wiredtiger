## What this FIXME asks for
Several statistics macros — specifically `WT_STATP_CONN_SET`, `WT_STATP_DSRC_INCRV`, and `WT_STATP_DSRC_DECRV` — do not have atomic (thread-safe) equivalents, unlike `WT_STAT_CONN_INCR_ATOMIC` / `WT_STAT_CONN_INCRV_ATOMIC`. Currently, data races on these non-atomic paths are suppressed at the TSAN level via `__wt_tsan_suppress_*` wrappers rather than being properly fixed. The FIXME asks that proper thread-safe versions of all these macros be created (using actual atomics) and that all call sites be updated to use the correct variant, eliminating the TSAN suppression wrappers. The related WT-15752 FIXME (in the same file at line 182) tracks removing the TSAN suppression wrappers themselves.

## Importance: MEDIUM
**Reasoning**: The use of TSAN suppressions to mask data races rather than fixing them means real concurrency bugs could go undetected. Statistics are low-criticality (inaccurate counts do not affect correctness), but corrupted 64-bit counters on non-atomic architectures could cause unexpected negative values or torn reads. More importantly, suppressing TSAN warnings for statistics may also hide genuine data races in the surrounding code paths that are harder to isolate.

**Gap**: There are no targeted tests for thread safety of statistics macros. The TSAN suppression wrappers effectively blind the testing infrastructure to any races on the affected code paths.
