## What this FIXME asks for
At API_END (the macro that closes out every public API call), there is an assertion that at most 3 history store (HS) cursors remain open. The ideal invariant would be zero open HS cursors, but nested API macro calls make it impossible to enforce this strictly. The FIXME asks for the nesting behavior to be refactored so that a strict "no open HS cursors on API exit" assertion can be introduced.

## Importance: MEDIUM
**Reasoning**: History store cursor leaks can cause incorrect visibility decisions, memory leaks, and stale reads if a cursor is inadvertently reused or its state is left behind. The current loose bound (<=3) masks potential resource leaks that could grow under edge cases. It is not an immediate crash risk but could hide real bugs in future HS cursor management changes.
