## What this FIXME asks for
The `decompress` function pointer in `WT_COMPRESSOR` takes a non-const `uint8_t *` for its input buffer, but the caller (`__read_decompress`) holds a `const void *` pointer to the read-only compressed data. To call the decompressor the code currently casts the const away via `(uint8_t *)in + WT_BLOCK_COMPRESS_SKIP`. The FIXME asks to fix this properly — either by changing the compressor API to accept a `const` pointer or by copying the input into a mutable buffer before decompressing.

## Importance: LOW
**Reasoning**: Casting away const is a code-quality and portability concern. The compressor interface contract does not actually modify its input; the cast is safe in practice. However, it may silently suppress compiler warnings and could theoretically cause undefined behaviour if a compressor extension were to write through the pointer. No crash or data-corruption path is present today.

## Test Coverage: COVERED
**Relevant tests**: test/suite/test_compress01.py, test/suite/test_compress02.py, test/format/wts.c
**Gap**: The decompression path is well exercised by compression smoke-tests and the format test with lz4/snappy/zstd compressors. The const-cast itself is not a behavioural gap, so no additional tests are needed; the fix is purely an API/signature cleanup.
