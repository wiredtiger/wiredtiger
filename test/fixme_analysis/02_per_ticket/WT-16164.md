| src/schema/schema_create.c:697 | __wt_config_merge expects that the config array passed to it is not sparsely populated. If the first element is NULL the config merge will not return anything useful. This ternary achieves that semantic. However there is likely a better, holistic fix here. |

## What this FIXME asks for
`__create_colgroup` defines `sourcecfg[] = {config, NULL, NULL}` and later writes `fmt.data` into index 1. The `config` parameter can legitimately be NULL, producing a sparsely-populated array `{NULL, fmt.data, NULL}`. `__wt_config_merge` iterates via `for (; *cfg != NULL; ++cfg)`, so a NULL at index 0 causes it to stop immediately and ignore the actual format data at index 1. The current ternary workaround places `fmt.data` at index 0 when `config` is NULL. The FIXME asks for a holistic review of all `__wt_config_merge` call sites across the codebase to identify any similar latent bugs, and for a proper fix that does not rely on this ad-hoc ternary.

## Importance: MEDIUM
**Reasoning**: If the ternary workaround were absent or incorrectly maintained, column-group creation with a NULL config would silently produce an empty merged configuration, leading to tables being created with missing or default format/value settings. This is a correctness bug with potential data-format mismatches. The workaround currently patches this specific call site, but other call sites that pass sparsely-populated arrays to `__wt_config_merge` may be silently broken.

## Test Coverage: PARTIAL
**Relevant tests**: test/suite/test_schema*.py; schema_create unit tests
**Gap**: No test explicitly passes a NULL config to colgroup creation to exercise the ternary workaround, nor are there tests that validate the `__wt_config_merge` sparse-array behavior. A codebase-wide audit of all `__wt_config_merge` call sites (requested by the FIXME) has not been completed.
