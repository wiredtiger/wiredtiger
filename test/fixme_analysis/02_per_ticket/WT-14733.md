## What this FIXME asks for
When `WT_CONNECTION::reconfigure` is called with a `disaggregated.checkpoint_meta` value, the leader silently ignores it. The rationale is that a node that was previously a follower may have the `checkpoint_meta` value baked into its saved base configuration, and that stale value should not be re-applied after step-up to leader. The FIXME asks for a proper solution: either strip the `checkpoint_meta` value from the base config at step-up time, or make the leader explicitly validate and reject/ignore it with a diagnostic message rather than silently discarding it.

## Importance: MEDIUM
**Reasoning**: Silent suppression of a reconfigure option is operationally dangerous: a caller that passes `checkpoint_meta` to a leader believing it will be applied (e.g., during a rolling upgrade or role-transition sequence) will get no error and no effect, making the system appear to accept the configuration while actually ignoring it. This could cause the leader to run with a stale checkpoint view if the silent-ignore logic ever had a bug, leading to incorrect data serving.
