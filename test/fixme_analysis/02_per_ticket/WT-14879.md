## What this FIXME asks for
When reconciling a child page that is in the `WT_REF_DELETED` state (fast truncate), the delta generation path is deliberately disabled: `build_delta` is set to false and `r->delta.size` is reset to zero. The FIXME asks for delta generation to be supported during fast truncate reconciliation so that fast-truncated pages can produce incremental page deltas instead of forcing a full page write, which is important for disaggregated storage performance. A reviewer comment (Alexander Gorrod, 2025-08-15) questions whether delta support is actually necessary here or just needs behavior verification.

## Importance: MEDIUM
**Reasoning**: Page deltas are a key mechanism for reducing write amplification in disaggregated storage. Disabling delta generation for fast truncates means all fast-truncated pages write full page images, negating delta efficiency for workloads that combine fast truncate with disaggregated storage. This is a performance concern (not a correctness bug), but it is significant for the intended use case. The ticket is P4 and in backlog, suggesting the team has not yet prioritized it, and there is active debate about whether the optimization is even needed.
