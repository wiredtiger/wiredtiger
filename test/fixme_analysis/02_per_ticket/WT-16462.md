## What this FIXME asks for
In `__create_table`, layered-table detection currently works by parsing the `type=layered` config key and then constructing the stable component URI by convention (`file:<tablename>.wt_stable`). While this is functionally correct today, the approach is fragile: changes to naming conventions or config handling could silently break shared-metadata updates. The FIXME asks for a more robust, future-proof method to identify layered tables and derive the stable component URI.

## Importance: MEDIUM
**Reasoning**: The current approach functions correctly, but if the stable component naming convention changes or the config parsing logic evolves, the metadata update could be silently skipped or targeted at the wrong URI, corrupting shared metadata for disaggregated tables. This is a technical-debt risk in the disagg storage path, not an immediate bug.
