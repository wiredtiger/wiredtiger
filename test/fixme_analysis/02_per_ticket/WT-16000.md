## What this FIXME asks for
WT-15982 added an optional `metadata_checksum` field to the `checkpoint_meta` configuration string used by a follower node when picking up a checkpoint. The FIXME marks a temporary backward-compatibility path: when the checksum is absent the code only logs a warning rather than rejecting the configuration. Once all producers reliably emit the checksum, it should be made a required field and the warning/fallback path removed.

The companion test (`test_layered64.py`) explicitly exercises the missing-checksum code path and notes that this leniency should be removed once the field is required.

## Importance: MEDIUM
**Reasoning**: Missing checksum allows silent data-integrity bypass during checkpoint pickup on follower nodes. Until enforced, a follower could pick up a checkpoint whose metadata integrity has not been verified, increasing the risk of undetected corruption in a disaggregated-storage deployment. However, the warning log provides visibility and producers are expected to emit the checksum already.

## Test Coverage: PARTIAL
**Relevant tests**: test/suite/test_layered64.py (explicitly tests the missing-checksum warning path)
**Gap**: There is no test that verifies the future enforcement path (i.e., that an error is returned when the checksum is absent). The test currently validates the lenient/warning behavior that will need to be inverted once WT-16000 is resolved.
