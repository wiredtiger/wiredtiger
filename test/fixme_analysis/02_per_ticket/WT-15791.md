## What this FIXME asks for
WiredTiger can return EBUSY from `compact`, `drop`, and `salvage` when a checkpoint is running concurrently; tests that call these functions directly fail spuriously in that case. The base test class (`wttest.py`) was extended with `compactUntilSuccess`, `dropUntilSuccess`, and `salvageUntilSuccess` helpers that retry on EBUSY (following the same pattern introduced for `verifyUntilSuccess` in WT-15662). The FIXME asks that all Python tests be audited and their direct `session.compact/drop/salvage` calls be replaced with the appropriate retry helper. Currently 66 Python test files contain direct calls that may still be vulnerable to EBUSY failures.

## Importance: LOW
**Reasoning**: This is a test-reliability improvement, not a production code issue. Direct calls cause intermittent, hard-to-reproduce test failures rather than correctness problems. The risk is noise in CI (false failures) rather than data loss or incorrect behavior.

## Test Coverage: PARTIAL
**Relevant tests**: test/suite/wttest.py (helpers defined), 66 Python test files in test/suite/ (still use direct calls)
**Gap**: The retry helpers exist but are not yet used consistently across the test suite. Any test calling `session.compact`, `session.drop`, or `session.salvage` directly can fail spuriously when a concurrent checkpoint holds the table lock.
