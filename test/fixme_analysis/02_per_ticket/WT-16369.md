## What this FIXME asks for
The `dumpErrorLogOnWtError` decorator in `wttest.py` currently only dumps the error log for `self.conn` (the leader connection) when a `WiredTigerError` is caught. Many disaggregated storage tests also open a follower connection (`self.conn_follow`). The FIXME asks that the error log for the follower connection be printed as well, to aid in diagnosing test failures in disagg configurations.

## Importance: LOW
**Reasoning**: This is a purely diagnostic improvement to test infrastructure. It does not affect production correctness or test coverage; it only improves the information available when a disagg test fails. The risk of leaving it unaddressed is that follower-side error context is lost during debugging, but no correctness is compromised.

## Test Coverage: COVERED
**Relevant tests**: test/suite/helper_disagg.py, test/suite/test_layered*.py (many files using conn_follow)
**Gap**: The underlying disagg test infrastructure is exercised by many layered tests. The gap is purely in diagnostic output: follower error logs are not emitted on exception, making triage of follower-side failures harder.
