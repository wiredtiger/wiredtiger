## What this FIXME asks for
`__clayered_adjust_state()` detects role changes (leader-to-follower or follower-to-leader) by comparing the current connection leader flag with the cached value in the cursor. However, if both a step-down and a step-up have both occurred between two consecutive state checks, `current_leader == clayered->leader` and `role_change` is false — the double transition is invisible. The FIXME notes that if this were detectable, a rollback should be issued for any pending writes on the stable cursor. In `test_layered31.py`, the step-down validation block (`Part 6`) is entirely disabled with `if False:` pending a fix.

## Importance: HIGH
**Reasoning**: A missed double role-change means that writes that should never be committed (they were made on a node that stepped down before being committed) could be silently lost or inconsistently applied. This is a correctness issue in the disaggregated storage leader/follower state machine. While the window for this race requires two role changes between cursor operations, disaggregated storage is a core MongoDB Atlas architecture component and correctness of role transitions is critical.
