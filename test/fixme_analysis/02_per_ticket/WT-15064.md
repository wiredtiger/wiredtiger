## What this FIXME asks for
Existing corruption and verification tests (`test_verify.py`, `test_corrupt01.py`) corrupt data by directly manipulating local files on disk. Disaggregated storage stores table data in PALI (Page Service) with no local file representation, so the same approach cannot be used. The FIXME tracks implementing corruption test cases for disaggregated storage using the PALM Python wrapper or a new C test API to locate and overwrite specific pages via the page log interface. The `hook_disagg.py` occurrence notes that `initialFileName()` has no equivalent for disagg, which blocks any test infrastructure that depends on knowing a table's backing file path.

## Importance: HIGH
**Reasoning**: Verification (`wt verify`) is a critical data integrity feature. Without corruption detection tests for disaggregated storage, bugs in the disagg verify path (e.g., failing to detect a corrupted page fetched from PALI, or silently treating a PALI read error as a missing page) would go undetected. Given that disaggregated storage is a new code path with its own page read/write mechanisms, the absence of corruption tests represents a significant gap in correctness coverage for a production feature.

## Test Coverage: UNCOVERED
**Relevant tests**: test/suite/test_verify.py (two helpers skipped), test/suite/test_corrupt01.py (entirely skipped under disagg hook)
**Gap**: No test injects data corruption into disaggregated storage and verifies that `wt verify` detects it. The `initialFileName` hook method returns None for disagg, breaking any test infrastructure that needs to locate and corrupt a table's storage.
