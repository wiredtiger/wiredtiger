## What this FIXME asks for
The test/format follower thread currently retrieves checkpoint metadata by calling `pl_get_complete_checkpoint_ext()` directly on the page-log interface. This works with the in-process mock PALI implementation used in testing, but the real DSC PALI library does not implement this function. The FIXME asks for the leader to push checkpoint metadata to the follower via an IPC mechanism (shared memory or pipe) at each checkpoint, so the follower can pick up new checkpoints without relying on a function that will not exist in production.

## Importance: MEDIUM
**Reasoning**: This is a test-infrastructure limitation rather than a production code bug. The test/format multi-node mode can only run against the mock PALI today; switching to the real DSC PALI library would break follower checkpoint pickup entirely. Until this is resolved, end-to-end integration testing of the leader/follower checkpoint handoff path is limited to the mock implementation and may not reflect real behavior.

## Test Coverage: PARTIAL
**Relevant tests**: test/format/follower.c
**Gap**: The follower checkpoint-pickup logic is exercised only with the mock `pl_get_complete_checkpoint_ext()`. No test path validates checkpoint propagation via the IPC mechanism that will be required for the production PALI library. The gap means multi-node disagg stress testing cannot run against real PALI without first implementing this handoff.
