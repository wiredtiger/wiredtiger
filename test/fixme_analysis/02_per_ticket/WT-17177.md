## What this FIXME asks for
As part of WT-17143, read-only connections with disaggregated storage were explicitly disabled by returning `ENOTSUP`. The FIXME marks locations where this limitation is enforced or worked around, and asks for a future investigation to determine whether read-only connection support should be implemented for disagg. The `wt -r` tool flag and read-only connection mode are used for offline inspection and debugging, so this gap may affect operational tooling. The question is whether the architectural complexity of supporting read-only disagg connections is justified by the use case.

## Importance: LOW
**Reasoning**: The restriction is intentional and explicitly guarded — attempting to open a read-only disagg connection returns a clear error message. The disaggregated storage model is write-heavy (leader/follower roles, shared page log) and read-only connections do not map naturally to this architecture. The operational impact is limited to debugging scenarios where `wt -r` is used against a disagg store, which is a niche use case. No production workload is blocked.

## Test Coverage: COVERED
**Relevant tests**: test/suite/test_layered88.py (test_readonly validates that ENOTSUP is returned); hook_disagg.py skips read-only tests; test_util23.py is skipped for disagg hook
**Gap**: The positive path (read-only connection being rejected) is tested. The negative path (what would happen if read-only were supported) is completely untested, but this is expected since the feature is not yet implemented.
