## What this FIXME asks for
`WT_LOG_V2_VERSION` (3.0.0) and `WT_LOG_V3_VERSION` (3.1.0) are defined as log format version boundaries, but `WT_MIN_STARTUP_VERSION` is 3.2.0, meaning WiredTiger will refuse to start on any database that predates 3.2.0. Since no database older than 3.2.0 can be opened, the code paths that handle log versions V2 and V3 can never be reached. The FIXME asks whether these dead definitions and their associated code can be safely removed.

## Importance: LOW
**Reasoning**: This is a code hygiene / dead-code removal issue. The version constants and their consumers in `log_mgr.c` will never be exercised given the startup minimum version check. Removing them would reduce complexity and maintenance burden, but failing to do so carries no correctness or performance risk.

## Test Coverage: UNCOVERED
**Relevant tests**: none found
**Gap**: There are no tests that verify behavior of log V2/V3 format files, which is consistent with those code paths being unreachable. Dropping the constants would require verifying that no compatibility test tries to open a pre-3.2.0 database file.
