## What this FIXME asks for
After WT-16565 changed metadata removal to be queued for the next checkpoint rather than synchronous, the `test_disable_idle_timeout_drop` test began failing under the disagg hook. The test asserts that cache memory decreases after dropping a table and waiting for the sweep server — but in disagg mode with release builds and table prefix, cache bytes unexpectedly increase before the sweep cleanup occurs. The FIXME asks for the root cause to be investigated and the test to be re-enabled on disagg once it passes.

## Importance: MEDIUM
**Reasoning**: This is an active test failure that masks a potential resource management bug in the disagg drop/sweep path. The behavior — cache bytes transiently increasing after a table drop — is anomalous and may indicate that deferred metadata removal causes extra in-memory structures to be pinned longer than expected. The test is skipped rather than fixed, hiding the issue. The ticket is assigned to Jie Chen.
