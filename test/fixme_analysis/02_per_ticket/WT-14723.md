## What this FIXME asks for
The import path (`__wt_import_repair`) currently rejects import of shared (disaggregated) tables with a hard `EINVAL` / "TODO" error. Before lifting that restriction, the shared file ID allocation scheme must be designed: importing a shared table requires assigning a file ID that does not conflict with IDs already used by other shared tables imported elsewhere in the cluster. Simply reusing a locally generated ID is insufficient and could cause collisions across nodes.

## Importance: MEDIUM
**Reasoning**: Import of shared/disaggregated tables is currently blocked at the API level with an explicit error, so no silent corruption can occur today. However, this means the import feature is entirely unavailable for disaggregated tables, which is a functional gap for production deployments that need to bring in data from external sources. When the restriction is lifted, a faulty implementation could produce file ID conflicts that corrupt the block manager's mapping between logical tables and physical files.
