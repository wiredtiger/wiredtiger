## What this FIXME asks for
In `check_prefetching_activity`, the test currently uses `assertGreaterEqual` (>=) for pre-fetch statistics (pages queued, prefetch attempts, pages read), which means a run that produces zero new activity passes as long as statistics have not decreased. The FIXME asks for these to be strengthened to `assertGreater` (>), i.e., strict increase, so the test actually confirms that pre-fetching activity occurred rather than merely not regressing.

## Importance: LOW
**Reasoning**: This is a test-quality issue. The weak `assertGreaterEqual` check means a prefetch regression (where no prefetching occurs at all) could go undetected if the baseline stats are zero. Strengthening to `assertGreater` would make the test a true positive signal for prefetch activity, improving bug detection fidelity.

## Test Coverage: PARTIAL
**Relevant tests**: test/suite/test_prefetch02.py
**Gap**: The test file itself is the only reference. The current `assertGreaterEqual` checks may not catch a prefetch bug where statistics fail to increase, because the check passes even if both old and new values are equal (including both zero).
