## What this FIXME asks for
The short-term fix in WT-16974 blanket-prevents the sweep server from ever closing any layered dhandle, because sweeping a layered dhandle while the node is a follower can cause data loss during the subsequent step-up drain (the layered table state is lost). The FIXME defers a proper long-term optimization: layered dhandles whose ingest table is known to be empty could be safely closed by the sweep server, and dhandles on a leader node (where the ingest table is not being drained during step-up) could also be eligible. The real work is to tie the lifetime of a layered dhandle to its ingest dhandle and add the logic to check these conditions before sweeping.

## Importance: MEDIUM
**Reasoning**: The current blanket exclusion of all layered dhandles from sweep means that in a long-running disaggregated deployment, the dhandle table will grow indefinitely as tables are created, potentially increasing memory usage and degrading sweep/checkpoint scan performance. This is a resource leak/performance concern rather than an immediate correctness risk (the short-term fix is safe). However, on systems with many layered tables, the memory and performance impact could become significant over time.
