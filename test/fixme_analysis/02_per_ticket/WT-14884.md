## What this FIXME asks for
During reconciliation wrapup, when a root page is found to contain no records (empty and durable), the code currently unconditionally calls the block manager checkpoint routine with a NULL image for the disaggregated storage path. The FIXME asks whether the page service layer (SLS/PALI) actually requires this empty-root-page write to correctly maintain its checkpoint metadata, or whether the write is unnecessary overhead that can be removed.

## Importance: LOW
**Reasoning**: The current behavior errs on the safe side by writing the empty root page regardless. The worst case if the write is truly unnecessary is wasted I/O to the page service; there is no known correctness risk. However, if the write turns out to be required and is later removed without proper validation, checkpoints for empty tables could become inconsistent in disaggregated storage.
