## What this FIXME asks for
The `disaggregated.last_materialized_lsn` reconfiguration parameter allows callers to advance the last materialized LSN by passing it through `WT_CONNECTION::reconfigure`. The FIXME notes that this functionality is now superseded by `WT_CONNECTION::set_context_uint`, making the old config path redundant. The ask is to formally deprecate (and eventually remove) the parameter from the public configuration API to reduce API surface and avoid dual-maintenance of two code paths that do the same thing.

## Importance: LOW
**Reasoning**: The existing parameter continues to work correctly; the risk is purely API hygiene and the possibility of callers depending on the old parameter after it should have been replaced. The ticket is in Backlog status with no assignee and no development activity, suggesting it is not blocking anything. The redundant path is a small code block that is straightforward to remove once callers are confirmed to use `set_context_uint`.

## Test Coverage: PARTIAL
**Relevant tests**: The reconfigure path in `src/conn/conn_layered.c` is exercised by disagg integration tests that reconfigure LSN settings.
**Gap**: There is no dedicated test that explicitly exercises the `disaggregated.last_materialized_lsn` reconfiguration parameter and verifies its effect, nor a test that validates the equivalence of the old parameter path with the new `set_context_uint` path.
