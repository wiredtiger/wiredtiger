## What this FIXME asks for
The `WT_STAT_DECRV_ATOMIC_BASE` macro (and its increment counterpart) uses `__wt_atomic_sub_int64` / `__wt_atomic_add_int64`, which default to sequential-consistency (seq-cst) memory ordering. Since statistics only need to be eventually consistent and do not guard any critical-section entry, seq-cst is unnecessary overhead — especially on ARM/POWER where seq-cst requires expensive full memory barriers. The FIXME asks for an evaluation and potential replacement with relaxed-order atomic RMW operations, after TSAN validation and performance benchmarking confirm correctness and speedup.

## Importance: MEDIUM
**Reasoning**: MEDIUM. This is a performance optimization opportunity, not a correctness bug. The seq-cst atomics are correct but slower than necessary, adding memory-fence overhead on every stat increment/decrement in hot paths (e.g., per-operation counters in reconciliation and eviction). The impact is highest on high-core-count ARM systems.
