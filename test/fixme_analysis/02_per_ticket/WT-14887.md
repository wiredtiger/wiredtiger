## What this FIXME asks for
Both `__wti_rec_kv_copy` (reconciliation) and `__wt_cell_kv_copy` (cell encoding) accept a bare output pointer without a maximum size parameter. As a result, there is no guard against a buffer overrun if the caller provides a buffer that is smaller than the data being written. Currently, only specific fixed-size data types flow through these functions, keeping the code safe in practice, but adding a `max_len` parameter and a bounds assertion would make the interface inherently safe for future use.

## Importance: LOW
**Reasoning**: There is no current known buffer overrun because call-sites are tightly controlled. However, the absence of a size parameter is a latent footgun: any future caller that passes a smaller-than-expected buffer will cause a silent heap corruption rather than a clean assertion failure. The risk is a memory safety issue (heap corruption / potential security concern) but only if the code is extended carelessly.
