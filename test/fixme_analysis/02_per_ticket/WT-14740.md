## What this FIXME asks for
Salvage (the operation that recovers data from a corrupt WiredTiger file) has not been implemented for disaggregated storage. The underlying block manager interface changed to accept a `WT_PAGE_BLOCK_META*` parameter (WT-14532), and the salvage code passes NULL for this, which is not valid in the disagg context. The FIXME asks for a design decision on how salvage should behave in disagg: whether it should operate on the ingest/local tables only, consult shared storage, or simply be forbidden. Currently, all salvage calls are intercepted by the disagg hook and skipped.

## Importance: MEDIUM
**Reasoning**: Salvage is a last-resort data recovery operation. For disaggregated storage, corruption recovery semantics differ fundamentally because data lives in shared object storage — local file corruption may be a non-issue (shared data is still intact), but local ingest table corruption could cause data loss. Without salvage support, any corruption in a disagg deployment has no automated recovery path. Several test classes (test_salvage*, test_prepare_hs03) are completely skipped under the disagg hook due to this gap.
