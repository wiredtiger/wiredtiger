## What this FIXME asks for
When live restore is active and WAL logging is enabled, the code that cleans up "stop files" from the log directory constructs the log directory path by concatenating the destination home with `log_mgr.log_path`. This construction is only correct when `log_path` is a relative path. An `WT_ASSERT` explicitly guards against absolute paths at line 1092. The FIXME asks for that restriction to be lifted so that users who configure `log=(path="/absolute/path/to/logs")` can also use live restore.

## Importance: MEDIUM
**Reasoning**: The limitation causes a hard assertion failure (not a graceful error) if a user configures live restore together with an absolute WAL log path. MongoDB's default configuration uses a relative log path, so the failure is not triggered by a standard deployment, but it is an undocumented restriction that will crash the engine if hit. The assertion should at minimum be converted to a proper error return.
