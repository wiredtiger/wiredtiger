## What this FIXME asks for
The `pl_abandon_checkpoint` PALI interface function was originally optional, used only in testing contexts. The check for `== NULL` exists as a compatibility shim that silently no-ops if the PALI implementation hasn't provided this function. The FIXME asks to remove this null-check guard and make the function mandatory, treating an absent implementation as an error rather than a silent skip. This aligns with the broader WT-16507 work that began enforcing PALI function implementations.

## Importance: MEDIUM
**Reasoning**: As long as the null-check guard exists, a PALI implementation that omits `pl_abandon_checkpoint` silently skips checkpoint abandonment, which could leave the page log in an inconsistent state after a failed checkpoint on the leader. This is a correctness risk for any PALI backend that has not yet implemented the function. Once all production PALI implementations support it, the guard should be removed to make missing implementations visible.

## Test Coverage: PARTIAL
**Relevant tests**: test/suite/test_layered*.py (checkpoint-related layered tests)
**Gap**: No test directly exercises the code path where `pl_abandon_checkpoint` is NULL to verify the warning is emitted. More importantly, once the guard is removed, tests need to ensure all PALI test stubs implement the function — that gap is not currently covered.
