## What this FIXME asks for
In disaggregated mode, WiredTiger currently writes local files to disk and then wipes them on startup via `__wti_ensure_clean_startup_dir`. The FIXME asks for a thorough review of which local files are actually written during disagg operation and whether they can be eliminated or reduced. Some local files (notably the metadata file) can grow large enough to require eviction during RTS, creating performance and correctness risk. The end goal is to avoid the startup directory-wipe entirely, which in turn removes the need for the `lose_all_my_data` guard that currently gates cleanup.

## Importance: HIGH
**Reasoning**: The current workaround (wipe-on-restart) requires MongoDB callers to pass a destructive `lose_all_my_data` configuration flag, meaning any missed or misconfigured invocation leaves stale, potentially inconsistent local files that could corrupt recovery. Large metadata files triggering eviction during RTS have already been observed in production paths (noted in ticket description). A related child ticket WT-15176 was spun off, indicating the scope is non-trivial.

## Test Coverage: PARTIAL
**Relevant tests**: `test/suite/` disagg integration tests exercise restarts in disagg mode; `test/format/` disagg stress configs exercise the startup path.
**Gap**: There are no targeted unit or integration tests that verify exactly which local files are created during a disagg session and assert that none (or only expected ones) remain after a clean shutdown. The correctness of the directory-wipe logic is not independently verified; it is only exercised incidentally during broader disagg restart tests.
