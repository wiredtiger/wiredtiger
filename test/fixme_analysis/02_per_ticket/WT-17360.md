## What this FIXME asks for
The `WT_CURSTD_CONSTITUENT_DEAD` flag is set on layered cursors in `__session_close_cursors` (session_api.c) immediately before calling `cursor->close()`, to prevent `__clayered_close_cursors` (cur_layered.c) from attempting to close the constituent ingest and stable cursors a second time when the session itself is closing (since `connection->close` closes all session cursors). The FIXME asks whether this flag is actually necessary — it may be that the cursor close sequence is now structured in a way that double-close can't occur without the flag, making it dead protection code.

## Importance: LOW
**Reasoning**: The flag is a defensive mechanism to prevent double-close of constituent cursors during session shutdown. If it is truly unnecessary (i.e., the cursor close sequence already prevents double-close), it is dead code that adds complexity and confusion to the cursor lifecycle. However, if removed prematurely, it could reintroduce a double-close bug (use-after-free on constituent cursors) during session teardown — a crash-level bug. Investigation is warranted but the current behavior is correct and safe.

## Test Coverage: PARTIAL
**Relevant tests**: test/suite/test_layered*.py (exercise layered cursor open/close lifecycle), WT-16479 tests for use-after-free bugs in layered cursors
**Gap**: There is no dedicated test that verifies the double-close protection specifically. The flag's necessity can only be confirmed by removing it and running the full test suite with address sanitizer or valgrind, looking for use-after-free errors during session close.
