## What this FIXME asks for
The layered cursor (`cur_layered.c`) manipulates `session->ncursors` (the count of active cursors) directly in `__clayered_enter`/`__clayered_leave`, but the read-committed snapshot release mechanism in the underlying file cursor code relies on `ncursors` reaching zero to decide when to release the snapshot. The layered cursor workaround (resetting constituent cursors when `ncursors` would hit zero) is a symptom of incorrect ownership of this counter. Additionally, there is a secondary bug where opening a cursor on the stable table can unexpectedly return `WT_NOTFOUND`, requiring defensive fallback logic in the merge iterator. A performance investigation showed fixing the `ncursors` behavior reduces p99 latency by ~22%.

## Importance: HIGH
**Reasoning**: The incorrect `ncursors` management causes `test_error_info02` to fail under the disagg hook and has a measurable performance impact (p99 latency regression of up to ~22%). More critically, read-committed snapshot semantics depend on `ncursors` being correct; if a snapshot is held longer than intended, stale reads can occur, violating isolation guarantees. The ticket has an active assignee (Jie Chen) and performance data making it a high-priority correctness and performance issue.
