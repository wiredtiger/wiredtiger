## What this FIXME asks for
The bulk-load cursor (`WT_CURSOR` opened with `"bulk"` or `"bulk,append"` configuration) is not implemented for layered/disaggregated tables. In `cur_layered.c` an explicit error is returned ("Layered trees do not support bulk loading"). The format stress tester disables bulk loading when `DISAGG_ENABLED` is set. Multiple Python tests skip their bulk-load test cases when running against the disagg hook. The FIXME asks for a working bulk-load path for layered cursors.

## Importance: MEDIUM
**Reasoning**: Bulk loading is a performance optimization for initial data ingestion, not a correctness requirement. MongoDB uses bulk load internally during initial sync and collection imports. Without it, disaggregated storage falls back to normal insert operations which are significantly slower for large datasets. There is no crash or data-corruption risk — bulk load is simply unavailable, and the code correctly rejects attempts to use it.

## Test Coverage: PARTIAL
**Relevant tests**: test/format/bulk.c, test/suite/test_checkpoint_snapshot05.py, test/suite/test_timestamp05.py
**Gap**: All three affected test locations skip the bulk-load path for disagg. The feature gap is well-documented with skip guards, but no positive coverage exists for bulk load with layered tables.
