## What this FIXME asks for
When picking up a disaggregated checkpoint, the `database_size` field in checkpoint metadata is currently optional — if absent, `has_database_size` is left false and the size is not populated. This fallback exists to maintain compatibility during the rollout of checkpoint size support (WT-16542/WT-16664). Once all nodes reliably populate `database_size` in checkpoint metadata, the conditional path, `has_database_size` field, and `WT_ERR_NOTFOUND_OK` fallback should be removed and the field made mandatory.

## Importance: LOW
**Reasoning**: The fallback is safe and intentional. Missing `database_size` only means size statistics will be unavailable for that checkpoint, not that data is corrupted. The risk is that the optional-field code paths persist indefinitely, accumulating technical debt and obscuring the true invariants. Once the field is mandatory, missing it would be an early indicator of a malformed checkpoint metadata entry.
