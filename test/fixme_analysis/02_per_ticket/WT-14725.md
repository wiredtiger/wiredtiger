## What this FIXME asks for
After creating the stable constituent of a layered table, `__create_layered` enqueues a shared-metadata operation (`WT_SHARED_METADATA_CREATE`) via `__wt_disagg_enqueue_metadata_operation`. The FIXME notes that if this creation is part of a composite operation (e.g., creating a layered table that contains multiple files), this enqueue may fire redundantly for each constituent, causing extra shared-metadata round-trips. The fix is to batch or deduplicate these enqueues when table creation spans multiple constituent tables.

## Importance: LOW
**Reasoning**: The current behaviour is functionally correct — extra metadata operations are idempotent and will not corrupt data. The risk is performance: extra shared-metadata enqueues add unnecessary network/storage overhead during bulk table creation in disaggregated deployments. For a single table creation this is negligible; at scale (DDL-heavy workloads) it could become a bottleneck.
