# test_import11 — Import tiered tables using backup:export cursor and metadata_file option

**File:** `test/suite/test_import11.py`
**Storage mode:** Tiered (skipped for non-tiered; has a separate local-only path tested via `@skip_for_hook("tiered")`)
**Components under test:** schema/import, tiered storage, backup:export cursor, metadata_file import option, statistics

## Test Cases

### `test_import11.test_file_import`
- **What it tests:** Creates two tables, exports them via a `backup:export` cursor (producing `WiredTiger.export`), then imports them in a new directory using `import=(enabled,repair=false,metadata_file="WiredTiger.export")`. For tiered scenarios, additionally verifies that using `file_metadata` instead of `metadata_file` is rejected with an appropriate error.
- **Components:** `src/schema/schema_create.c`, `src/tiered/`, `src/backup/backup_cursor.c`, `src/stat/`
- **Notes:** Parameterized by tiered storage sources (generated by `gen_tiered_storage_sources()`).

  Tiered-specific error cases tested:
  - `file_metadata` with tiered → `"import for tiered storage is incompatible with the 'file_metadata' setting"`
  - `file_metadata` + `metadata_file` combined → same error
  - `import=(enabled,repair=false)` with no metadata → `"Invalid argument"`

  Stats verified: `stat.conn.session_table_create_import_success` increments with each successful import. `stat.conn.session_table_create_import_fail` increments for each rejected attempt.

  Note: Verification step is currently commented out (`FIXME`) due to known failure on tiered storage.
